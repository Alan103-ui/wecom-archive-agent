二、商业化能力差距矩阵

按优先级分级：P0 地基 不过关不能卖；P1 产品化 决定能否规模化；P2 增值 拉开与竞品差距。

P0数据库升级SQLite → PostgreSQL（并发、JSONB、向量检索、备份）换引擎、方言适配、迁移脚本

三、三阶段演进路线

阶段1 · 地基（0–3 月，P0）：多租户隔离 + PostgreSQL + 容器化 + 安全审计 + 合规脱敏 + License。目标：能接第一批私有化交付客户，数据不串租户、部署可复制。
阶段2 · 产品化（3–6 月，P1）：SaaS 计费订阅 + 模型路由降本 + 前端重构移动端 + 监控可观测 + 模板可配置。目标：开放自助试用/订阅，规模化获客。
阶段3 · 增值（6–12 月，P2）：数据洞察报表 + 多生态集成 + 私有化发行 + 模板市场 + AI 辅助处置。目标：提升客单价与续费率，建立壁垒。

四、关键风险与决策点

  • 合规是最大红线。企业微信会话存档属强监管场景（员工须知情、数据须合规留存与脱敏）。合规能力应先于功能扩张建设，否则无法过客户法务与等保。
  • 路线分叉：私有化 vs SaaS。两者对架构影响巨大（私有化重离线授权/信创，SaaS 重多租户/计量）。建议双轨并行：内核统一，交付层分流，避免后期返工。
  • 模型成本决定毛利。当前强依赖外部大模型，需尽早做模型路由（按风险等级选模型）、结果缓存、批处理，并提供私有化模型选项，否则大客户用量会吃光利润。
  • 前端技术债。vanilla JS 在商业化迭代中会显著拖慢速度，应在阶段2 前完成框架化重构，否则功能越多越难维护。

五、最小可卖 MVP 建议

若希望尽快产生收入，建议阶段1 收口即对外交付私有化版，暂不建 SaaS：

  • 交付物：Docker 镜像 + 部署脚本 + License 激活 + 合规脱敏 + 操作审计。
  • 目标客户：对数据主权敏感的中大型企（金融、制造、政企），单笔私有化授权 + 年维保。
  • 同时并行做 PostgreSQL 与多租户，为阶段2 SaaS 铺路。
  • 节奏：3 个月出私有化 MVP → 6 个月 SaaS 试运营 → 12 个月增值生态。
本方案基于 wecom-archive-agent 全量代码审计（app/ + frontend/ 共 77 个 py + 前端 2664 行）与功能完成度评估生成。所有改造项均可映射到现有代码模块，工作量可在立项后细化拆解。
